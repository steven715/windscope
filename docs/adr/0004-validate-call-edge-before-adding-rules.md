# ADR-0004：新增規則／資料源前，先用現有資料驗證盤前判斷有沒有 edge

- **狀態**：Accepted
- **日期**：2026-10-29
- **脈絡背景**：使用者檢視專案後指出，系統每天給一個方向，但「對自己沒什麼太大的幫助，
  遠不如直接讓 AI 模型分析」。追問後釐清：目標是勝率與獲利，而目前的規則來源（文章＋影片）
  門檻是經驗值，命中率沒有基準線對照、信心沒驗過校準、命中率也沒換算成交易勝率——
  所以不知道該信多少、也不知道該調什麼。本 ADR 把「先驗證再擴規則」定成工作順序。

---

## 脈絡（Context）

- 盤前判斷的門檻（匯率 ±0.05、價差 ±100、外資未平倉 ±3 萬口）來自原文經驗值，原文作者自承
  「沒科學根據」；兩票合成與信心加減分是代碼自創（`docs/logic_article.md` §0）。
- 既有驗證層只給「近 N 筆命中率」與各信心命中率（`verification.get_verification_stats`），
  沒有基準線、沒有信賴區間、沒有把命中率換成有成本的交易報酬。
- 60 筆命中率 60% 的 95% 區間約 ±12pp，與 50% 無法區分；每天一筆一年只有 ~240 筆。
- 直接問 LLM 的「感覺比較有幫助」來自它綜合敘事的能力，但它不記分、不可驗證；系統能做而
  LLM 做不到的正是記分。

## 決策（Decision）

1. **順序**：在加任何新資料源、新規則、新門檻之前，先用**現有資料**跑 `integration/call_stats`
   （`/stats`）四張表，確認目前規則處於「有 edge／可能有／看不出／樣本不足」哪一格。
2. **統計層純離線唯讀**：不改門檻、不寫 DB、不動排程、不 bump `SIGNAL_RULE_VERSION`。
   它只攤開既有驗證的後果，不產生新立場。
3. **結論四選一的規則固定在 `_assess`**：系統 Wilson 95% 區間下界 > 最強基準 → 有 edge；
   平均 > 基準但區間蓋住 → 可能有；否則看不出。樣本 < `STATS_MIN_SAMPLE` 一律樣本不足。
4. **命中率與勝率分開用字**（GLOSSARY）：命中率只講方向對不對、勝率只講照著做有沒有賺。
5. **LLM 的位置**：讀 `/api/call-stats` 的結構化戰績＋當日盤前輸入做綜合建議；系統不講故事、
   LLM 不碰原始資料與統計。

## 理由（Rationale）

1. **先知道有沒有 edge，再談怎麼調。** 沒有基準線的命中率無法解讀；台股長期偏漲，「永遠喊偏多」
   本身就可能有五成以上命中。調門檻前不先量，等於在雜訊上做參數擬合。
2. **信心校準是最便宜的檢驗。** 信心 1–5 若與命中率無單調關係，整套加減分邏輯該砍，不該再疊規則。
3. **方向對 ≠ 賺錢。** 偏多命中賺 0.4%、偏空失誤賠 2%，命中率七成照樣虧；要看期望值與盈虧比。
4. **單因子表決定下一步加什麼。** 哪個輸入各桶漲跌分布無差 → 是擺設；有差 → 值得加權或細分。
   這比憑感覺再加一個資料源有依據。
5. **與 ADR-0001 一致**：資料量極小，全部 stdlib 迴圈，顯式逐筆、無未來函數。

## 承擔的代價（Consequences）

- 在樣本累積到門檻前，`/stats` 多半顯示「樣本不足」——這是正確的誠實結果，不是 bug；
  不因此放寬 `STATS_MIN_SAMPLE`。
- 單日 open→close 回測口徑簡化（不考慮滑價、漲跌停、零股），只用來比較規則版本的相對優劣，
  不代表實盤績效。
- 新增規則／資料源的提案，需附上「現有四張表哪一格支持這個改動」。

## 替代方案（Alternatives considered）

- **直接加更多資料源／規則**：在不知道現有規則有無資訊量前，只會把雜訊疊高、更難歸因。否決。
- **引入 ML 模型**：CLAUDE.md 明列不做；且樣本量不支撐。否決。
- **只靠 LLM 分析、不記分**：不可驗證、無法迭代。否決——LLM 要放在記分板之後，不是取代它。

## 何時重新考慮（Revisit triggers）

- 已驗證樣本 ≥ 200 筆且結論穩定為「看不出 edge」→ 回頭檢討兩票合成與門檻來源，而非再加規則。
- 結論為「有 edge」且信心單調 → 可開始接多日持有／跟大勢出場的判斷回測，再談加權。
